# 通常 Issue 対応フロー

この文書は、通常の Issue 対応で使用する標準フローです。

Codex は、原則として以下の順番で作業してください。

## Phase 0: Issue Clarification

まず Issue を読み、内容を理解してください。

実装前に、以下を短く整理してください。

- Issue の目的
- 期待される動作
- 変更が必要そうな範囲
- 不明点
- 仮定してよいこと、仮定してはいけないこと

### 実装に進める場合

以下を明記してから次に進んでください。

- 理解した Issue 内容
- 前提条件
- 変更範囲
- 進め方

### 実装に進めない場合

Issue が曖昧で実装判断できない場合は、人間に質問してください。

質問は最大 5 個までに絞ってください。
各質問には以下を含めてください。

- 不明点
- なぜ確認が必要か
- 推奨する選択肢
- 推奨理由

詳細は以下を参照してください。

- `docs/codex/workflows/clarification.md`

## Phase 1: Investigation

変更対象と影響範囲を調査してください。

調査対象の例:

- 関連ファイル
- 関連関数
- 関連クラス
- API
- 画面
- 設定ファイル
- テスト
- データ構造
- エラー処理
- 既存仕様

小さく局所的な修正であれば、Codex 本体が直接調査して構いません。

以下に該当し、ユーザーが agent 利用を明示している場合は、`explorer` agent を使って追加調査してください。

- 変更範囲が広い
- 影響範囲が読みにくい
- 既存仕様や実行経路の把握に時間がかかる
- 複数の候補実装があり、先に証拠を集めた方がよい

この段階では、原則としてファイル編集は禁止です。

調査結果として、以下をまとめてください。

- 変更が必要なファイル
- 影響を受ける可能性があるファイル
- 既存の処理の流れ
- 既存テストの有無
- リスク
- 推奨する実装方針

## Phase 2: Design Check

以下のいずれかに該当する場合は、設計確認を行ってください。通常は Codex 本体で実施し、ユーザーが agent 利用を明示した場合のみ適切な agent を使います。

- 変更範囲が複数モジュールにまたがる
- 責務分担が曖昧
- DB、ファイル形式、API 仕様に影響する
- セキュリティ、認証、権限に関わる
- 将来の保守性に影響しそう
- 実装方針が複数あり迷う
- 非機能要件への影響がある

設計確認では、以下を確認してください。

- 推奨方針
- 代替案
- 採用しない案とその理由
- リスク
- 最小実装手順
- 必要なテスト

詳細は以下を参照してください。

- `docs/codex/workflows/design_check.md`

## Phase 3: Implementation

Codex 本体で実装してください。

実装時のルール:

- 最小限の変更で対応する
- 関係ないファイルを変更しない
- 不要な大規模リファクタリングをしない
- 既存仕様を勝手に変えない
- 既存の設計、命名、書き方に合わせる
- エラー処理を無視しない
- 既存テストがある場合は、それに合わせて追加・修正する

実装中に Issue の解釈が変わった場合は、作業を止めて人間に確認してください。

## Phase 4: Validation

関連テストを実行してください。

確認対象の例:

- 単体テスト
- 結合テスト
- Lint
- Type check
- Build
- 該当機能の手動確認

テストが失敗した場合は、以下を整理してから修正してください。

- 失敗したコマンド
- エラー内容
- 原因
- 修正方針
- 再実行結果

テストが実行できない場合は、理由を明記してください。

## Phase 5: Review

実装後、差分の大きさやリスクに応じて差分レビューを行ってください。通常は Codex 本体で実施し、ユーザーが agent 利用を明示した場合のみ適切な agent を使います。

レビューを強く推奨するケース:

- 変更範囲が複数ファイルにまたがる
- セキュリティ、認証、権限、個人情報に関わる
- DB、ファイル形式、API 仕様に影響する
- 既存仕様への回帰リスクがある
- ユーザーがレビューを明示した

レビュー観点:

- バグ
- 回帰リスク
- セキュリティ
- テスト不足
- エラー処理
- 保守性
- 仕様の取り違え

レビュー担当はファイルを編集せず、指摘だけ行います。
Codex 本体は、指摘内容を確認し、妥当なものだけ修正してください。

詳細は以下を参照してください。

- `docs/codex/workflows/review_only.md`

## Phase 6: Final Summary

最後に日本語で以下をまとめてください。

## 対応内容

- 何を変更したか
- なぜ変更したか

## 変更ファイル

- 変更したファイル
- 主な変更点

## テスト結果

- 実行したコマンド
- 結果
- 未実行のテストがあれば、その理由

## 残リスク

- まだ不明な点
- 人間に確認してほしい点
- 将来対応した方がよい点
